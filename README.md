# Альфа-Дент — обновление существующего Mini App и текущего MAX-бота

**Это пакет обновления текущего проекта, а не предложение создавать второй сайт или новый Mini App.** Существующий публичный адрес сохраняется:

`https://alfadent-miniapp.onrender.com/miniapp.html`

## Состав

- `web/miniapp.html` — существующий интерфейс, дополненный MAX Bridge; сохраняет поддержку Telegram WebApp.
- `webapp_api.py` — API существующего приложения; валидирует Telegram `initData` и MAX `window.WebApp.initData` перед созданием заявок.
- `bot_telegram.py` — текущий Telegram-бот; функция создания заявки теперь помечает канал и поддерживает создание заявки из общей Mini App API.
- `web/assets/promotions.json` — единый файл 10 предложений, используемый Mini App и MAX-ботом.
- `max_bot_current.py` — новая версия обработчика текущего MAX-бота (Flask webhook). Это не отдельный веб-сайт.
- `max_bot/` — копия скрипта и локальная копия акций для развёртывания MAX-бота отдельно от API.

## 1. Обновление уже существующего Render-проекта Mini App

1. Сделайте резервную копию текущего репозитория и переменных окружения.
2. Перенесите в **тот же существующий проект** файлы `web/miniapp.html`, `web/assets/promotions.json`, остальные нужные актуальные файлы из `web/assets/`, `webapp_api.py`, `bot_telegram.py` и `requirements.txt` из этого пакета. Не меняйте имя Render-сервиса и публичный URL.
3. В переменных окружения существующего Render-сервиса добавьте `MAX_BOT_TOKEN` — **новый действующий токен текущего MAX-бота**. Оставьте `TELEGRAM_TOKEN` с новым/действующим Telegram-токеном для проверки запуска Telegram. Настройте `BITRIX24_WEBHOOK`, `BITRIX_ASSIGNED_BY_ID` и `BITRIX_ADMIN_IDS` корректными значениями.
4. Оставьте существующую команду запуска API, если она уже использует `uvicorn webapp_api:app --host 0.0.0.0 --port $PORT`. Если Render использует другую команду, не заменяйте её вслепую — сохраните текущую рабочую схему.
5. После деплоя проверьте `/health`. В ответе должны быть `ok: true`, `crm_configured: true` и `max_validation_configured: true`.

`BITRIX_ADMIN_IDS` — это именно ID сотрудников Bitrix24, а не ID пользователей Telegram или MAX. `BITRIX_ASSIGNED_BY_ID=33` оставлен в примере из текущего проекта; перед запуском подтвердите, что это нужный сотрудник.

## 2. Обновление текущего MAX-бота

1. На том сервере/сервисе, где уже работает webhook MAX, замените текущий файл обработчика содержимым `max_bot_current.py` (или используйте `max_bot/max_bot.py`, если сервис запускает код из папки `max_bot`). Сохраните текущий сервис и публичный адрес webhook; новый Render-сайт для этого не нужен.
2. Установите зависимости из `requirements_max.txt`, если их ещё нет.
3. Задайте переменные из `max_bot/.env.example` на существующем MAX-сервисе. Обязательно укажите **новый** `MAX_BOT_TOKEN`, новый `BITRIX24_WEBHOOK`, `MAX_BOT_USERNAME` существующего бота (без `@`) и реальные сопоставления `MAX_ADMIN_TO_BITRIX`, если используете распределение задач по сменам.
4. Если `MAX_WEBHOOK_SECRET` пуст, webhook доступен по `/webhook`. Если задаёте секрет, зарегистрируйте webhook с путём `/webhook/<тот_же_секрет>`.
5. Файл акций в папке `web/assets/promotions.json` нужен как резервная локальная копия; при доступности текущего Mini App бот сначала скачивает акции по `PROMOTIONS_URL`.

## 3. Привязка существующего Mini App к существующему MAX-боту

Это делается в кабинете MAX для партнёров, а не кодом Python:

1. Откройте **Чат-боты → текущий бот MAX → ⋮ → Настройки**.
2. В поле URL Mini App задайте ровно `https://alfadent-miniapp.onrender.com/miniapp.html`.
3. Выберите тип кнопки открытия и сохраните настройки.
4. В переменной `MAX_BOT_USERNAME` укажите публичное имя этого же бота без `@`. Тогда inline-кнопка в меню будет иметь тип `open_app` и откроет именно привязанное Mini App в контексте MAX. Пока имя не настроено, скрипт намеренно не показывает обычную ссылку на веб-страницу как кнопку открытия приложения: при открытии во внешнем браузере MAX `initData` недоступен, поэтому отправка заявки должна быть заблокирована. После сохранения URL в MAX Partner Portal платформа также покажет собственную кнопку запуска Mini App в чате.

Официальная документация MAX: https://dev.max.ru/help/miniapps и https://dev.max.ru/docs/webapps/validation.

## Что меняется в поведении

- MAX `/start` показывает меню без обязательной авторизации.
- В чат-меню есть 10 согласованных разделов: запись, визиты, экстренная помощь, врачи, услуги и цены, акции, о клинике, администратор, отзывы, рекомендации.
- Услуги при записи — 9 согласованных позиций. Проблема «Выпала коронка / мост» исправлена на «Выпала коронка».
- Акции считываются из того же `web/assets/promotions.json`, что Mini App; каждая открывается отдельной карточкой с кнопкой «Записаться по акции».
- Экстренное обращение запрашивает проблему, комментарий и телефон.
- Бот не показывает фиктивные визиты, не имитирует реальное подтверждение или отмену и не обещает, что пожелание по дате является свободным слотом.
- В Mini App подключён `https://st.max.ru/js/max-web-app.js`; запросы к API отправляют `platform` и `initData`, API проверяет подпись MAX/Telegram на сервере.
- Код `1234` оставлен как временный код. SMS реально не отправляется, а код не подтверждает номер через поставщика SMS.

## Ограничения, которые остаются

- МИС «Инфоклиника» не подключена: реальные свободные окна, реальные визиты, подтверждение, перенос и отмена существующего визита требуют API-доступа и документации МИС.
- Не подтверждены все связи «услуга → врач», специализации, длительности и актуальные цены. В этих местах код не должен выдумывать данные.
- Для части акций в исходном Excel нет срока действия; карточки специально сообщают, что администратор должен подтвердить актуальность.
- Ссылки на отзывы/соцсети и публичное имя MAX-бота нужно сверить перед публикацией.
- Заявки в CRM и доставка сообщений MAX/Telegram в этой среде не тестировались с настоящими ключами. После установки нужен тестовый проход на реальных сервисах.

## Секреты

Токен MAX и вебхук Bitrix24 были раскрыты в старом исходном файле. Отзовите/смените их до запуска и внесите новые значения только в конфигурацию сервера. Никогда не коммитьте `.env` в GitHub.
